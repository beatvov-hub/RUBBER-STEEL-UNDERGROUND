# RUBBER STEEL UNDERGROUND

Windows向け見下ろし型ローグライト・アクションシューティング。Version 1.0.0。50ステージ×各10フロア、計500フロアを収録しています。

自分が撃った弾は敵に命中するまで消えず、RUBBER STEELの壁で何度でも跳ね返ります。跳弾は自分にも当たり、敵を全滅させた後もフロアを出るまで残ります。未破壊の装甲に当たった弾も消費されず、装甲を壊して反射します。

## 遊ぶ

[readme_ja.txt](readme_ja.txt)に動作環境、操作方法、保存先、配布時の注意事項を記載しています。Windows配布版は`release/RUBBER_STEEL_UNDERGROUND-1.0.0-win.zip`を展開し、`RUBBER_STEEL_UNDERGROUND.exe`を起動します。プレイヤー側にNode.jsのインストールは不要です。

- `WASD` / 矢印キー: 移動
- マウス: 照準、左クリック: 射撃
- `1` / `2` / `3`: STANDARD / TRIPLE SHOT / HEAVY SHOT
- `Esc`: 一時停止、`R`: 死亡時のフロア再挑戦

最初はSTAGE 1だけが解禁されています。各ステージの10フロアを突破すると次のステージが開きます。FIRE、ICE、THUNDERはそれぞれSTAGE 10、20、30のクリアで解禁されます。2・4・6・8階の脱出時には18種類の一時能力から3候補が提示され、1つ選択します。死亡時には取得した一時能力が失われます。

エリアが進むにつれてフロアの総敵数が増加します。1ステージあたりの合計はSTAGE 1が59体、STAGE 2–10が各63体、STAGE 11–20が各100体、STAGE 21–30が各145体、STAGE 31–40が各198体、STAGE 41–50が各258体です（ボスを含む）。FLOOR 10はボスと取り巻きが登場し、FLOOR 9以上の敵数を維持します。STAGE 21以降のFLOOR 10はFLOOR 9より取り巻きを3体増やし、取り巻きの半数以上が装甲敵です。STAGE 1のボスは単発射撃で基本を教え、以降のエリートボスは予告後に2発扇状射撃を行います。STAGE 10・20・30・40・50のエリアボスは専用プロフィールに応じて1〜3発を撃ちます。敵は初期最大12体で、残りは最大6体ずつ増援として加わります。増援地点は約2秒前に表示され、プレイヤーが近くにいる間は出現を延期します。

STANDARDは精密な単発射撃、TRIPLE SHOTは3方向への同時射撃で近接集団への対処に向きます。外した弾も3発とも残ります。HEAVY SHOTは弾速が遅い代わりに威力3・半径8で、ボスや装甲解除後のHP2を持つ装甲敵に強い武器です。装甲への最初の命中は武器を問わず反射します。ゲーム中の武器HUDには選択中の役割を表示し、各切替ボタンには特徴と注意点を説明しています。

後半には3体クラスターが登場し、各組に非装甲敵が2体以上含まれるため、TRIPLE SHOTで複数体を狙いやすい配置です。外した弾も永久に跳ね返るため、集団への射撃は危険も高めます。

## ビジュアル

5つのエリアごとに床・照明・アクセントカラーを切り替え、工業施設から最深部へ進む変化を表現しています。兵士と敵は輪郭や装備を見分けやすい小型キャラクターとして描画し、武器・キャラクターごとの色、発射反動、被弾フラッシュ、移動アニメーションで戦闘状態を伝えます。弾道と跳弾にはトレーサーや発光を付け、自弾と敵弾を色と形で区別します。HUD、フロア名、警告表示、能力選択画面もゲーム内の工業施設の意匠に統一しています。

## 開発と検証

Node.js 22以降を使用します。

```powershell
npm ci
npm run dev
npm test
npm run verify:content
npm run build
npm run package:win
```

`npm run dev`はローカルのViteサーバーを起動します。`npm run desktop`はビルド後にElectronで起動します。`npm run package:win`はWindows用ZIPを`release/`に生成します。テストの内容は以下のとおりです。

| コマンド | 検証内容 |
| --- | --- |
| `npm test` | 永久跳弾、自弾被弾、装甲反射、武器・能力、キャラクター、ギミック、進行、セーブ移行などの単体テスト |
| `npm run verify:content` | 全500フロアの生成、敵・増援地点への到達性、壁・ギミックの配置、ステージ別敵数、生成フォールバックを一括検証。`-- --profile`を付けるとエリア・階層別の平均敵構成、ギミック、部屋タイプを集計 |
| `npm run test:playthrough -- 50 thunder adaptive` | 固定シードの自動操縦で指定ステージを確認し、死亡原因、フロア時間、フロア別の死亡数・敵数と自弾数のピーク・武器別の使用弾数と撃破数・反射数を出力。引数はステージ、キャラクターID（省略時`standard`）、武器方針（`standard`、`triple`、`heavy`はその武器に固定、`adaptive`は状況で切り替え）、開始フロア（省略時1）の順。`adaptive`は集団にはTRIPLE、ボスや装甲解除後にはHEAVY、未破壊装甲にはSTANDARDを選びます。検証時は`--fire-interval=2.4`で射撃間隔を、`--ability=first`または`--ability=random`で能力選択方針を変えられます（既定は1.1秒間隔・`slow`優先） |
| `npm run test:browser` | `http://127.0.0.1:5174`で起動中の画面に対するブラウザーテスト |
| `npm run test:desktop` | `npm run package:win`後の`release/win-unpacked`に対するEXE起動テスト |
| `npm run test:debug` | `http://127.0.0.1:5175/?debug=1`で起動中の開発用デバッグ画面のテスト |

ブラウザーテストには、別のターミナルで`npm run preview -- --port 5174`を起動します。デバッグ画面のテストには`npm run dev -- --port 5175`を起動します。PlaywrightのテストはMicrosoft Edgeを使用します。

現行の敵数・増援・クラスター構成での自動操縦測定は[VALIDATION.md](VALIDATION.md)に記録しています。自動操縦は武器やステージ間の比較に使う検証用モデルです。実際の遊びやすさ・公平性を確定する人間によるプレイ評価は、まだ完了していません。

## 実装の構成

- `src/data.ts`: ゲーム定数、初期ステージ、4キャラクター、3武器、18能力。
- `src/world.ts`: 5エリア・50ステージ、シード付きフロア生成、テンプレートと配置検証。
- `src/engine.ts`: 描画から独立した固定120Hzシミュレーション。180発上限、弾オブジェクト再利用、敵AI、可動壁・崩落床、ステージ進行。
- `src/save.ts`: バージョン2のローカル保存、旧セーブからの移行、ステージ・キャラクター解禁。
- `src/main.ts`: 操作、メニュー、設定、Web Audioによる効果音・BGM、Canvas描画との接続。
- `src/visuals/`: エリア別フロア、兵士、弾道・反射・発光演出、能力アイコンの描画。
- `electron/main.cjs`: ビルド済みのローカルファイルを読み込むWindowsアプリ。
- `tests/`、`scripts/`: ルール、500フロア、ブラウザー、EXEの検証。

フロアはステージ定義、部屋テンプレート、敵構成、可動壁・崩落床を組み合わせて決定的に生成します。生成時に出口や敵への経路とギミックの安全性を検査します。自弾は時間や反射回数で削除せず、敵への命中またはフロア移動時のみ消去します。

開発サーバーでは`?debug=1`を付けると、全ステージ解禁、ステージ・フロア移動、キャラクター選択、無敵、敵・増援数、武器別射撃・撃破数、弾数、シード、フォールバック状態、ヒットボックス、描画時間の表示を使用できます。リリースビルドではデバッグ画面を表示しません。
